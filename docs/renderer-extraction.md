# Local Line renderer extraction

Source provenance: Locus `4cce6ebfaa31f76cd7790967ad8ce7d7e2338deb`, paths `AgentWorldWeb/src`, `AgentWorldWeb/tests`, `AgentWorldWeb/index.html`. The combined audit was committed in Locus as `d7f05e63` before implementation transfer. These paths are historical: the thin-host cutover removed them from active Locus inputs after the native acceptance gate. Original source remains in Git history and the independently verified recovery archive. Source artwork ownership and hashes are recorded separately in the asset manifest.

The Local Line package owns Babylon rendering, sailing/pathfinding, ships/styles, harbor reservations, island crew, ocean/shaders, scenery, camera, labels, decorative effects, world HUD, and standalone quarters preview. The LocalLineRenderer class contains only ocean behavior. Campus geometry, desks/props, robot/human/panda actors, Outpost palette, catalog selection/default/fallback, beacon viewport, and campus CSS/HTML have been removed from the active implementation; their source and tests remain in the verified recovery artifact described by the Locus audit.

`localLineWorld.ts` implements the SDK World interface. `main.ts` exports a transport-independent asynchronous UI factory; neither file discovers WebKit or creates synthetic profiles. The plugin composition owns actual transport and explicitly opts into the separate mock harness. The world translates its private nautical preferences and presentation IDs into generic SDK commands. Native chats, agent creation, activity, approval flows and hosted management surfaces remain host commands. Pure rendering never submits tasks or messages.

The manifest identity is `local-line`; `grand-line` survives only as an internal source-artwork/configuration compatibility slug. SDK and Core do not import it. Required capability is `agents.read`; `agents.interact` and `world.preferences` are optional. Controls recompute permission availability from the live context on every host projection, so a handshake received after initialization enables granted controls and revocation can disable them. Host enforcement remains authoritative.

## Lifecycle and clocks

Initialization allocates the scene but starts no Babylon render loop. Core supplies the initial authoritative snapshot before activation. Snapshot delivery seeds historical transfer IDs; later host events animate only unseen deliveries. Changing session/scope/stream clears the prior visible projection. Rendering is delegated to the world's existing single Babylon scene loop and one bounded alert viewport; `World.render(frame)` schedules nothing.

World and alert loops use wall time only to limit GPU redraws to their existing 30/20 FPS. Visual simulation and event freshness use the injected context clock, preserving deterministic pause/step while allowing asynchronous model uploads, camera input and labels to redraw. Browser verification identified and corrected redraw starvation when an initial implementation used a paused mock clock for both purposes. Delta remains capped at 50 milliseconds, preserving the baseline protection against jumps after hidden/resumed frames.

Deactivation stops both loops. Disposal is idempotent, aborts model/configuration fetches, releases scene and alert GPU resources, clears labels and preview cards, closes the preview dialog, aborts every bootstrap listener, cancels note timers and invalidates late initialization. The existing HTML shell is reset on initialization and disposal, including panel expansion, dialogs, searches, loading/fallback indicators and accessibility attributes. Identity assignment caches prune against the full authorized roster, preserving paging while discarding removed or previous-workspace IDs. The wrapper forwards lifecycle cancellation into the pending UI factory before it returns. A graphics-constructor failure releases the partially constructed scene and engine.

`Reset world settings` delegates only to the context's scoped world storage reset. It has no direct access to UserDefaults, profiles, chats, tasks, board/calendar state, or filesystem paths. Browser localStorage and implicit demo persistence have been removed; development uses the same storage contract through its explicit mock host.

## Regression-test disposition

The original renderer baseline passed 144 tests. The extracted Local Line suite retains/adapts **128** existing Local Line/shared behavior tests and adds **8** SDK World-wrapper tests, for **136 passing tests**, zero failed/skipped/cancelled, on Node v25.5.0. `npm run typecheck` also passed.

The 16 intentionally unshipped tests were Outpost-only: five crewAssignments, three pandas, three people, two non-ocean newsCoo variants, one resident appearance snapshot, one campus-prop parser, and one Outpost activity-language test. They remain recoverable with the original source. All other test files migrated. Mixed tests retain their ocean/generic assertions: the theme catalog expectation now proves a single Local Line configuration and safe fallback, invisible console obstacles are absent at ocean berths, ship rotation tests use the Local Line manifest, and generic movement tests use a small explicit navigation fixture instead of depending on production campus geometry. Invalid ocean bounds retain Local Line's safe default band. Tests still cover full-hull route clearance, no collisions, broadside docking, working-state reservations and release, stable styles/identity, reduced motion, sea effects, model geometry/rotation, labels and camera behavior.

New wrapper tests cover no invented roster or initialization loop; historical snapshot vs event transfer handling; cross-scope clearing; native command mappings; namespaced reset; read-only preference rejection; cancellation during asynchronous initialization and late result cleanup; validation of private preferences; and manifest/SDK metadata consistency. Browser/native acceptance results are recorded separately; these unit and NullEngine tests do not by themselves establish SwiftUI/WebKit parity.

## Remaining acceptance limits

The supported Document is the plugin's own HTML shell. Standalone quarters is a decorative preview with crew locating, not an implementation of native chats/forms. SDK optional capabilities can hide/disable native intentions, but native authorization must still reject forged messages. Browser failure and visual evidence does not substitute for native artifact loading, install/upgrade/rollback, canonical-work survival, or plugin-absent Locus tests. These have separate evidence in [verification](verification.md) and the matching Locus migration reports, including the passing final native app-host aggregate and the remaining verification limits.
